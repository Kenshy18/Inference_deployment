# 3時間 自律動作・品質・速度検証（2026-07-29）

## 結論

現時点の推奨経路である「6 NVENC workerの高速overlay」は、15分と5時間の
両方でフレーム欠損、重複、PTS/DTSの飛び、分割境界の非keyframe、decode errorを
生じなかった。5時間・431,935 frameの最終マスク＋顔overlayは、描画・encode・
結合が222.09秒（1,944.90 FPS）、オーケストレーターの事前検証込みで360.72秒
だった。active render中のCPU RSSおよびVRAMに線形増加はなかった。

現行コードから新規に実行した1,440 frameの一気通貫smokeも、推論、先行cut検出、
GPU楕円後処理、統合SQLite、raw/tracked/final/facesの高速overlayまで43.75秒で
完了した。4本の出力は全て厳密検証を通過した。

短時間matrix、反復、5時間、通常経路、sanitizer、追加modeを合わせ、最終出力
単位で72 run、延べ2,085,886 frameをrenderした。

ただし、次の2点は区別して扱う必要がある。

1. CPU `veryfast`とNVENCを1本の出力内で混在させる高速hybridは、フレーム数は
   正しくても分割境界のDTSが不等間隔になる。現行defaultのままでは採用不可。
2. 5時間テスト用の反復入力は元音声自身に15分ごとの0.218667秒gapを19個含む。
   audio stream copyはそのgapを保存するため、音声付き5時間出力のstrict validation
   は音声decode連続性だけfailする。15分の実入力では音声を含め全項目passした。

## CPU＋NVENC hybridの発生条件

15分final＋facesで切り分けた。

| 構成 | FPS | H.264 B-frame | avg frame rate | DTS |
|---|---:|---:|---:|---:|
| CPU 6、veryfast | 1,214.57 | 2 | 24/1 | uniform |
| NVENC 6 | 1,780.78 | 0 | 24/1 | uniform |
| CPU 1＋NVENC 5、veryfast | 1,829.54 | 混在 | 129612/5401 | 境界1個で異常 |
| CPU 3＋NVENC 3、veryfast | 1,657.26 | 混在 | 129612/5401 | CPU→NVENC境界で異常 |
| CPU 3＋NVENC 3、ultrafast | 2,091.32 | 0 | 24/1 | uniform |

CPU 3＋NVENC 3 veryfastでは分割frame 3,601、10,802、18,002の直前から次packet
までが0.125秒になり、別の境界では極小stepを伴う。CPUのみではB-frameのdecode
orderが一貫するため問題なく、NVENCのみもB-frameなしで問題ない。異なるreorder
特性のsegmentをstream copy concatしたときだけ生じる。

`ultrafast`はB-frame 0になりDTS問題を避け、速度も最大だった。ただし
Constrained Baseline profileとなり、同じ8 Mbpsでもsegmentごとの画質特性が異なる。
純NVENC出力とのVMAF比較は次の通り。

- 全体VMAF mean: 96.7498
- float SSIM mean: 0.996455
- PSNR-Y mean: 43.6463 dB
- libx264 segment VMAF mean: 95.0603
- NVENC segment VMAF mean: 98.4394
- 境界±3 frame VMAF mean: 98.6421、min 89.9851
- 非境界VMAF mean: 96.7468
- hybrid容量: 879,297,491 bytes
- pure NVENC容量: 901,110,335 bytes

境界固有の画質低下やframe shiftは検出しなかったが、encoderごとの画質差はある。
したがって当面は6 NVENCを推奨する。hybridを正式採用するなら、CPU側を
B-frame 0に固定した上で、profile、GOP、rate control、color metadataも揃えた
同条件品質検証が必要である。

- overlay video: 431,935 frame、全video check pass
- audio: AAC 48 kHz、843,429 packet
- audio packet PTS: strictかつ連続

ない。反復テスト素材の作り方、またはvalidatorのsource-relative判定を改善する
べきである。

- segmentの逆転またはframe範囲外
- segment外keyframe
- 同一segment内のkeyframe index/frame重複
- componentを持たないkeyframe
- 非正の楕円半径
- 3点未満のpolygon ring
- polygon point indexの欠番・重複
- 不正なface ellipse

capabilityとcomponent statusは、存在する機能を`complete`、未要求機能を
`not_requested`として区別している。schemaは`stable-all-modes-v2`、
frame indexは0 base、座標はsource display pixels、角度はradian、cutは
「新sceneの先頭frame」という契約を保持している。

2.23秒で違反0だった。検査processの最大RSSは15,908 KiBだった。
