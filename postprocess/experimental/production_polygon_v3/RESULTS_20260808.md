# Production Polygon V3 initial dual-Recall result

The experiment used SQLite polygon geometry only. No video frame was opened.

## Configuration

- source/baseline: old Production interval-10 SQLite;
- label: `男性器`;
- frames: 8,681--20,059;
- observations: 6,499 in 26 track/cut segments;
- normal minimum Recall: 0.97 per observed frame;
- screen-edge minimum Recall: 0.97 per touched side and observed frame;
- screen-edge strip: 24 pixels;
- Production-compatible off-canvas extent: required;
- original Production vertex count: retained per segment (21, 22, or 23).

V3 retained all 664 Production key positions, minimally changed 211 existing
key shapes that violated a hard constraint, and inserted 1,470 keys. The
constraint guard itself took 80.99 seconds; full load, audit, SQLite export,
reload, and second audit took 99.37 seconds wall time with a 295 MB peak RSS.

The first implementation is intentionally strict rather than sparse. The large
increase in key count quantifies the cost of applying both 0.97 floors literally
to every AI observation, especially the 3,149 observations touching a screen
edge. Subsequent V3 work should improve the key/area tradeoff without weakening
either minimum constraint or reintroducing a fixed global key budget.

## Soft-target penalty refinement

The second pass exposed every original AI observation as a conservative anchor
candidate, used old Production (not the strict V3 path) as the reference shape,
and minimized `sum(1 - IoU) + lambda * keyframe_count`. The requested mean
interval 10 was used only to calibrate lambda; it was never enforced as a key
budget.

| Active hard constraint | keys | actual interval | min normal Recall | min edge Recall | mean IoU |
|---|---:|---:|---:|---:|---:|
| both, 0.97 / 0.97 | 2,014 | 3.321 | 0.970003 | 0.970000 | 0.941563 |
| normal only, 0.97 | 1,875 | 3.571 | 0.970003 | n/a | 0.938931 |
| edge only, 0.97 | 687 | 9.989 | unconstrained | 0.970000 | 0.882462 |

All three files preserved the input schema fingerprint, passed SQLite integrity
and foreign-key checks, and had exactly zero editor-versus-Overlay geometry
difference on all 6,499 observations.

The ablation establishes that the full-mask per-frame minimum Recall is the
dominant source of extra keys. The screen-edge constraint alone can meet the
interval-10 target almost exactly. Adding it to the normal constraint costs a
further 139 keys (1,875 to 2,014), whereas normal Recall alone already requires
roughly 2.7 times the target count. Hitting lambda's configured upper bound while
remaining at 2,014 keys means interval 10 is not feasible in the current
conservative candidate graph. This is not a proof that no continuously optimized
polygon can achieve it; the next useful algorithmic step is continuous anchor
vertex optimization, not weakening the constraints or hard-fixing the key count.
